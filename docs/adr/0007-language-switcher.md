# Language switcher is a server-rendered block plus a shortcode

The switcher is a dynamic block, with no JS build step, and a `[kybernaut_ml_switcher]` shortcode. Both share the same renderer. Output is `<nav class="kbnt-ml-switcher">` with a plain list: the current language is a non-link `<span aria-current="page">`, and other languages link to the page's translation. Only a few lines of base CSS ship (no bullets, items in a row), enqueued only where the switcher renders; all other styling belongs to the theme. This was tightened from "no CSS" because an unstyled list renders with bullets in every theme.

Inside the core Navigation block (detected by the `openSubmenusOnClick` context only Navigation provides), the block renders plain `li.wp-block-navigation-item` items instead of its own `<nav>`, so it behaves like any menu link. It is added to Navigation's `allowedBlocks` with a client-side `blocks.registerBlockType` filter, because the editor reads that list from the bundled block metadata, not from PHP. A *Show current language* toggle (shortcode: `show_current="no"`) hides the current language.

When a translation is missing, a setting decides the behaviour: **hide that language** (default) or **link to that language's home** (its root, or `/` for the default language). Rendered markup is cached in the object cache, keyed by map version, view, language and locale. It is never written to the database: without a persistent object cache the markup is memoised per request, and rendering from the cached map is cheap anyway (ADR 0004). An earlier version stored it in a transient, but that wrote to the database on front-end requests and bloated autoloaded options, so it was dropped.
